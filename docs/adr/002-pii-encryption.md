# ADR-002: 민감정보는 저장소가 노출돼도 평문으로 드러나지 않게 저장한다

## Status

Accepted (2026-06-09)

> 이 ADR은 **정책**만 정의한다. 어떤 필드가 여기에 해당하는지의 인벤토리, 구체 알고리즘,
> 키 관리·회전 방식, 마이그레이션 순서 같은 **구현 디테일은 변경 시점의 spec/구현 결정에 위임**한다.

## Context

ADR-000은 authgate를 "인증 경계이자 토큰 발급기"로 정의했다. 그 정체성상 authgate는
가장 값비싼 사용자 식별 정보(PII)와 인증 크리덴셜을 보관한다.

위협 모델의 핵심은 **"읽기" 노출**이다. DB 덤프, 백업, 리드 레플리카, 로그·감사 유출처럼
권한 없는 누군가가 저장된 데이터를 읽기만 해도 사고가 된다. 이때 사용자 PII 원문이나
아직 살아있는 크리덴셜이 그대로 드러나서는 안 된다. 저장 시점에 이를 원천 차단할
일관된 정책이 필요하다.

## Decision

**PII이거나 그에 준하는 데이터는 평문으로 저장하지 않는다. 예외 없이 보호한다.**

어떻게 보호하는지(메커니즘이 아니라 방향):

- **원문 복원이 필요한 값**(표시·연락용 식별 정보 등) — 암호화해 저장하고, 복호화 키는 데이터스토어 밖에 둔다.
- **조회·매칭에만 쓰거나 소지가 곧 인증인 값**(식별자, 세션, 일회용·인가 코드 등) — 단방향 해시로 저장하고 원문을 보관하지 않는다. (가역이 필요 없으면 암호화보다 해시가 더 안전하다.)
- 가역(복호화 가능) 보관은 원문이 꼭 필요한 값으로 **최소화**한다.
- 키·pepper 같은 key material은 애플리케이션 데이터스토어에 저장하지 않는다.
- 계정 삭제 시 해당 PII는 복구 불가능해야 한다.
- 로그·감사 payload에 평문 PII·크리덴셜·key material을 남기지 않는다.

운영 제약:

- authgate는 프로덕션 운영 중이므로, 위 전환은 **무중단으로 점진 적용**한다.

## Non-Goals

- 노출돼도 PII가 아닌 값(권한·조인용 내부 식별자, 단명 프로토콜 값 등)의 전수 암호화는 대상이 아니다.
- 전송 구간 암호화(TLS)나 애플리케이션 외부 인프라 계층 암호화는 이 ADR의 범위가 아니다.
- 구체 알고리즘·스키마·롤아웃 순서 등 구현 결정.

## Consequences

### Positive
- 저장소·백업·로그가 유출돼도 PII 원문과 살아있는 세션/코드가 복원되지 않는다.
- 삭제 요청에 대해 PII를 비가역적으로 제거할 수 있는 토대를 만든다.
- "무엇이 민감정보인가"에 대한 공통 분류 기준이 생겨, 신규 기능도 같은 원칙을 따른다.

### Negative
- 암호화·해시·키 관리로 저장/조회 경로의 복잡도가 늘어난다.
- 가역 보관을 허용한 값은 키 유출 시 복원 위험이 남는다(그래서 최소화한다).
- 프로덕션 무중단 전환은 다단계 마이그레이션과 운영 절차를 요구한다.
